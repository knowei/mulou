# P0 UI：先定结构，后定视觉

## 0. 为什么分开

| 层 | 改一次的成本 | 现在做？ |
| --- | --- | --- |
| 信息架构（几个页面、怎么跳、每屏放什么） | 要动导航、状态、返回栈 | **现在做** |
| 组件结构（列表 vs 卡片、字段优先级） | 中等 | **现在做**（粗版） |
| 视觉（配色/字体/圆角/动效/图标） | 只改主题和组件参数 | **跑通后做** |

理由：Bangumi 的真实数据还没进来。封面是 2:3 还是 16:9、中文标题多长、时间表有没有空档、字段缺多少——这些直接决定视觉，现在拍脑袋等于返工。

## 1. 现有 UI 的三个结构性问题

1. **首页是规则列表**。规则是配置，不是内容。用户每天打开 App 想看的是"今天更新什么"，不是"我有哪些源"。
2. **没有底部导航**。只有"规则 → 搜索 → 选集 → 播放"一条线性路径，进不去"浏览"。
3. **没有空/错/离线状态**。规则全挂时界面就是白屏 + 一行报错。

## 2. P0 信息架构

底部三个 Tab：

```
┌─────────┬─────────┬─────────┐
│  追番    │  搜索    │  我的    │
│ (首页)   │         │         │
└─────────┴─────────┴─────────┘
```

| Tab | 内容 | 数据来源 |
| --- | --- | --- |
| **追番** | 继续观看 + 今日更新 + 本季新番 | 索引（离线可用） |
| **搜索** | 输入 → 本地索引联想 + 17 源并发兜底 | 索引 + 规则 |
| **我的** | 规则管理（导入/健康）、设置、关于 | 本地 |

原来的「规则页」降级成 **我的 → 规则管理**。选集/播放仍然是二级页面，从详情页进入。

### 2.1 首页（追番）

```
┌──────────────────────────────┐
│ 追番                          │
│                              │
│ 继续观看                      │
│ ┌────┐ 葬送的芙莉莲           │
│ │封面│ 第 8 集 · 12:34 / 24:00│
│ └────┘ ▓▓▓▓▓▓░░░░░░           │
│                              │
│ 今日更新（周五）               │
│ ┌────┐ ┌────┐ ┌────┐         │
│ │    │ │    │ │    │         │
│ └────┘ └────┘ └────┘         │
│ 芙莉莲  药屋   咒术            │
│                              │
│ 本季新番              全部 >  │
│ ┌────┐ ┌────┐ ┌────┐         │
│ │    │ │    │ │    │         │
│ └────┘ └────┘ └────┘         │
└──────────────────────────────┘
```

- 封面固定 **2:3**，圆角 8dp；
- 标题最多 2 行，超出省略；
- 角标显示「更新至第 N 集」（有数据才显示）；
- 没有观看记录时，「继续观看」整块隐藏，不留空壳。

### 2.2 时间表

放在「追番」Tab 内的分段，或独立入口（P0 先放首页一个「今日更新」即可，完整周表放 P1）。

```
周一 ─────────────────────
  · 20:00  某番            更新至 8
  · 22:30  另一部          更新至 3
周二 ─────────────────────
  ...
```

用**分组列表**而不是七列网格：手机竖屏下七列每列不到 50dp，标题没法看。

### 2.3 详情页

```
┌──────────────────────────────┐
│ ←                             │
│ ┌──────┐  葬送的芙莉莲         │
│ │ 封面  │  9.2 分 · 2023年秋   │
│ │      │  奇幻 / 冒险 / 治愈   │
│ └──────┘  全 28 集            │
│                              │
│ 简介（可展开）                 │
│                              │
│ [ 开始观看 ]  ← 主按钮        │
│                              │
│ 片源（点击展开）               │
│  ✓ AGE      7 线路            │
│  ✓ baimao   6 线路            │
│  ○ 7sefun   搜不到            │
└──────────────────────────────┘
```

关键：**详情以索引为主**，片源是"可用性列表"。某个源搜不到也显示出来（灰色），而不是隐藏——用户要知道"为什么这里没有"。

### 2.4 搜索

变化：输入两三个字就先出**本地索引候选**（瞬时），再并发打规则源。

```
┌──────────────────────────────┐
│ [芙莉莲            ] 🔍       │
│                              │
│ 索引（3）                     │
│  · 葬送的芙莉莲    2023秋     │
│  · 芙莉莲 第二季   2024冬     │
│                              │
│ 来自片源（15/17）              │
│ ✓ AGE · 2 条                 │
│ ✓ baimao · 2 条              │
│ ✗ moonci · HTTP 403          │
└──────────────────────────────┘
```

## 3. 组件与尺寸（粗规范，视觉阶段再调）

| 项 | 值 |
| --- | --- |
| 间距 | 4 / 8 / 12 / 16 dp |
| 页面左右边距 | 16 dp |
| 封面 | 2:3，圆角 8dp |
| 标题 | 14sp，2 行 |
| 次要信息 | 12sp，onSurfaceVariant |
| 列表项高度 | 72dp（两行） |
| 主按钮 | 通栏，高 48dp |

## 4. 状态设计（比视觉重要）

| 状态 | 表现 |
| --- | --- |
| 加载中 | 骨架屏（灰块），不用转圈 |
| 索引为空 | "还没有同步番剧数据" + 重试按钮 |
| 离线 | 顶部细条"离线，仅显示本地数据" |
| 某个源失败 | 该源分组头变红并给出原因，其他源不受影响 |
| 番无任何片源 | 详情页"暂无可用片源"，仍可追番 |

## 5. 迁移影响（现有代码怎么挪）

| 现有 | 去哪 |
| --- | --- |
| RulesScreen | 我的 → 规则管理 |
| SearchScreen | 搜索 Tab（保留并发分组 UI） |
| ChaptersScreen | 详情页里的「片源 → 线路」 |
| PlayerScreen | 不变 |

导航从"顶部返回栈"变成 "底部 Tab + 栈"，`Screen` 枚举要拆成 `Tab` + `Route`。

## 6. 明确延后的事

配色方案、字体、图标、动效、深色模式细节、平板布局、封面占位图风格——**等 P0 跑通、拿到真实数据后再统一做**。现在用 Material3 默认值 + 一个主色即可。

## 7. 结论

先做结构：底部三 Tab、首页（继续观看/今日更新/本季新番）、详情页以索引为主。
视觉等数据回流后再一次性统一——那时改的是主题参数，不是导航。

## 8. 落地情况（2026-10-18 已实现）

- 底部三 Tab：追番 / 搜索 / 我的；规则管理降级到「我的」
- 首页：今日更新（按星期）+ 本季新番（按评分），数据来自 Bangumi `/calendar`，**缓存优先**
- 详情页：封面/评分/放送日/简介 +「查找片源」并发搜全部规则，结果按源分组
- 选集、播放、规则导入保持不变

**MuMu 12 实测**：

| 项 | 结果 |
| --- | --- |
| 首页 | 109 部当季番；今日（周日）更新 4 部 |
| 详情 | 标题 / 6.4 分 / 2026-10-04 / 查找片源 |
| 找片源 | 17 源并发，「青之箱 第二季」9/17 有结果，耗时约 6.8 秒 |

**踩到的坑**：Bangumi 返回里存在 `"images": null`，kotlinx 默认会因为一条 null 丢掉整个列表——表现是首页整页空白、但没有任何报错。已加 `coerceInputValues` 并补了回归测试。

**环境限制**：当前网络下 `api.bgm.tv` **宿主机和模拟器都不可达**（`lain.bgm.tv` 的 AAAA 解析到 Facebook 网段，属于典型 DNS 污染；A 记录连接超时）。验证时用此前拉取的缓存注入设备，恰好验证了「缓存优先」这条设计：索引拉取失败时首页仍能渲染，只在顶部提示更新失败。

这也说明索引源不能只依赖单个域名，后续需要「可配置基址 / 本地导入索引 / 备用元数据源」里的至少一种。
