## 三、结论

1. **"80% 规则已死"得到独立验证**：仓库里 69 条被标 `deprecated`，全量跑下来 56% 连请求都发不通——两边对得上。
2. **失败里约 40% 是基础设施问题**（DNS/证书/超时/重置），不是选择器写错。这决定了产品设计：规则失败要**分类呈现**，不能只显示"搜索失败"——「域名解析失败」和「页面结构变化」对用户意味着完全不同的动作。
3. **302/301 值得处理**：有 4 条规则返回 3xx，说明站点做了跳转（换域名、强制 https）。跟随重定向并记录最终地址，能救回一部分规则。
4. **空结果 ≠ 坏规则**：12 条 0 结果里可能只是关键词不匹配，需要用多个关键词复测才能定性。

`HttpStatusException` → HTTP 状态码……），用户不用看堆栈。
